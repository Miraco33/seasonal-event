# 盛趣历史活动页兼容性

本记录用于验证采集器面对不同年份和活动模板时能否识别活动标题、任务、NPC 与时间。历史页面清单位于 `services/seasonal-event-collector/history-pages.json`，可在采集器目录执行：

```powershell
$env:PLAYWRIGHT_EXECUTABLE_PATH = "C:\Program Files\Google\Chrome\Application\chrome.exe"
npm run audit:history
```

加入 `-- --strict` 后，只要存在无法完整识别核心字段的页面，命令就返回非零状态。该工具只读取官方页面并向标准输出写结果，不保存整页 HTML、图片或用户数据。

现代模板的核心文本字段可以自动提取。官网写 `xx:59` 时，采集器把下一整分钟作为排他结束边界；官网写 `14:00` 等整点时保持原值，不再错误延长一分钟。

大多数抽样页面的任务位置都依赖地图图片，奖励也主要通过图片展示；2015 新生庆典等少量旧页会在正文中给出显示坐标，但仍缺少世界坐标。因此正式发布仍要求活动级 `LOCATION_OVERRIDES` 和必要的 `REWARD_OVERRIDES`。2019 等旧模板缺少正文时间时，应人工核对并补充结构化覆盖或另行使用 OCR。2015 模板还可能把新闻标题当成任务标题，或列出多个接取地点；审计清单用 `manualReview` 标记这些页面，不能把“字段非空”直接当作可自动发布。
