# 盛趣历史活动页兼容性

本记录用于验证采集器面对不同年份和活动模板时能否识别活动标题、任务、NPC 与时间。历史页面清单位于 `services/seasonal-event-collector/history-pages.json`，可在采集器目录执行：

```powershell
$env:PLAYWRIGHT_EXECUTABLE_PATH = "C:\Program Files\Google\Chrome\Application\chrome.exe"
npm run audit:history
```

加入 `-- --strict` 后，只要存在无法完整识别核心字段的页面，命令就返回非零状态。该工具只读取官方页面并向标准输出写结果，不保存整页 HTML、图片或用户数据。

## 2026-09-04 基线

当前清单共 36 个官方页面，其中 2025—2026 年样本 21 个：2026 年截至 9 月 4 日发现 7 个，2025 年发现 14 个。执行 `npm run audit:recent` 会只检查这 21 个现代模板，并要求 HTTP 成功、标题、任务、NPC、时间均可识别，且 NPC 与人工记录的预期名称一致。

最近两年样本的核心字段可识别率为 21/21，但这不等于数据已经完整，也不代表官方页面已经穷举。盛趣没有提供可验证的季节活动历史索引；例如搜索结果可以确认 2025 年 2 月另有一场恋人节活动，而当前仍未找到其可复验的官方详情页 URL。因此“21 个已发现样本全部通过”只能证明这些 URL 的模板兼容，不能证明两年内没有漏页。

现代页面的完整度缺口如下：

| 字段 | 2025—2026 样本结果 | 发布影响 |
|---|---:|---|
| 标题、任务、NPC、时间 | 21/21 可识别 | 仍需用预期 NPC 名称检查语义，不能只判断非空 |
| 任务等级 | 21/21 可识别 | 可直接使用 |
| 正文坐标 | 0/21 | 接取点主要在地图图片中，世界坐标仍需 `LOCATION_OVERRIDES` |
| 可直接提取名称的奖励候选 | 0/21 | 即使部分 `mob.html` 有可见奖励文字，当前发布仍需 `REWARD_OVERRIDES` |
| 任务 ID、成就 ID、传送目标 | 官网不提供 | 需要从可靠游戏数据人工核验后写入 `COMPLETION_OVERRIDES` |

现代模板的核心文本字段可以自动提取。官网写 `xx:59` 时，采集器把下一整分钟作为排他结束边界；官网写 `14:00` 等整点时保持原值，不再错误延长一分钟。

大多数抽样页面的任务位置都依赖地图图片，奖励也主要通过图片展示；2015 新生庆典等少量旧页会在正文中给出显示坐标，但仍缺少世界坐标。因此正式发布仍要求活动级 `LOCATION_OVERRIDES` 和必要的 `REWARD_OVERRIDES`。2019 等旧模板缺少正文时间时，应人工核对并补充结构化覆盖或另行使用 OCR。2015 模板还可能把新闻标题当成任务标题，或列出多个接取地点；审计清单用 `manualReview` 标记这些页面，不能把“字段非空”直接当作可自动发布。
